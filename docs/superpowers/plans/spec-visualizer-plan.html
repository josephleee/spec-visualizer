2.1 참고.

기능은 다섯 단계 중 하나에 있다.

미해결 질문이 남았는데 plan.md가 있으면 어느 단계로 보여주나요?

파일이 단계를 정한다. 맞는 규칙 중 가장 뒤 단계가 이긴다.

홈 화면은 현재 작업 중인 기능을 맨 위에 둔다.

설계는 .git/HEAD 파일을 읽는다. git worktree에는 그 파일이 없다.

현재 작업 중인 기능을 어떻게 찾나요?

체크박스는 ID가 있든 없든 센다.

spec-kit이 기능마다 이 파일을 만든다.

미해결 질문은 spec.md와 plan.md의 NEEDS CLARIFICATION 표식 개수다.

문서 종류마다 전용 페이지가 있다.

우선순위와 Given / When / Then은 파일에서 읽는다. 3.1 참고.

파서는 모르는 내용을 절대 버리지 않는다.

일부 구역만 인식되면 페이지는 무엇을 보여주나요?

페이지는 HTML 주석을 숨기고 다른 HTML은 글자로 보여준다.

주석은 AI에게 주는 작성 지침이고 문서 내용이 아니다.

페이지는 HTML 주석을 어떻게 처리하나요?

data-model 페이지는 엔티티마다 카드 하나를 보여준다.

관계 서술에는 정해진 형식이 없다.

첫 버전에서 엔티티 사이의 관계도를 그리나요?

모르는 이름의 파일은 마크다운 페이지로 보여준다.

모르는 이름의 파일은 어떻게 하나요?

전용 페이지 일곱 개는 문서마다 정해진 표식을 읽는다.

파일이 바뀌면 새로고침 없이 화면이 바뀐다.

서버는 파일 변경 한 묶음마다 이벤트 하나를 보낸다.

열어둔 페이지는 새 내용으로 바뀌고 스크롤 위치를 지킨다.

열어둔 페이지의 파일이 바뀌면 페이지는 무엇을 하나요?
설계 문서는 화면에 낡은 내용이 보이는 것을 실패로 본다. 이 선택은 그것을 잠시 허용한다.

홈 화면은 새 문서와 갱신된 문서를 표시한다.

브라우저는 사용자가 연 문서마다 값 하나를 저장한다.

열람 기록을 어디에 저장하나요?

프로젝트를 처음 열 때 모든 문서를 본 것으로 기록한다.

문서 14개인 프로젝트를 처음 열면 무엇이 보이나요?

내용 해시가 달라지면 문서를 “갱신됨”으로 본다.

설계는 파일 수정 시각을 비교한다. git checkout은 내용이 같아도 시각을 바꾼다.

문서가 바뀌었는지 무엇으로 판단하나요?

공통: 서버가 JSON으로 보내는 프로젝트 모델 하나.

화면의 라벨은 어떤 언어로 쓰나요?

바꾸지 않는 것: 프로젝트 파일, 다른 포맷, AI가 만드는 페이지.

  • 도구는 프로젝트에 파일을 쓰지 않는다. 편집도 체크박스 토글도 없다.
  • 갱신된 문서는 최신 내용만 보여준다. 무엇이 바뀌었는지는 보여주지 않는다.
  • OpenSpec과 Kiro 문서는 읽지 않는다.
  • 한 번 실행에 프로젝트 하나. 여러 프로젝트를 모아 보는 화면은 없다.
  • 정적 내보내기, 호스팅, 로그인은 없다.
